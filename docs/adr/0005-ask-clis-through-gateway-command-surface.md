# Ask the CLIs through one Gateway Command Surface port

The collector talks to the OpenClaw and Tailscale CLIs only through the Gateway Command Surface: seven named questions (Gateway status, node status, Fleet Nodes, Agents, Tasks, Automations, Tailscale devices) that each return the raw exit code, stdout, and stderr before the collection deadline. `collect_gateway` receives the adapter as a parameter. `main()` supplies the bounded child-process adapter and tests supply an in-memory answer table, so collection behaviour is specified through the collector's own interface rather than through a fake executable steered by environment variables or by patching internal functions.

The independent metadata questions run in four bounded threads after target validation, sharing the same deadline. Automation pages remain sequential within one worker. Adapters therefore support independent concurrent calls. Child processes launch through a small exec helper that sets Linux parent-death termination before exec, avoiding thread-unsafe `preexec_fn` while retaining process-group timeout cleanup.

Decoding stays on the collector side because a failed `gateway status` still carries structured JSON that separates Gateway Setup Required from Gateway loss; an adapter returning decoded payloads would have to reproduce that distinction. The collection deadline, the 8 MiB output bound, and process-group termination from ADR-0001 and ADR-0002 remain inside the child-process adapter. Incident notifications (`notify-send`) are not questions: they have their own 0.25-second timeout and stay outside the port.
